# 9. 国际化与英文术语

> [English version](../docs/i18n.md) · [返回中文文档索引](./README.md)

AgentBox 以共享资源包本地化 renderer、Electron 主进程、preload 可见错误、原生系统对话框、备份说明和内置 Agent/Skill 文案。目前支持简体中文与英文。

## 语言选择与持久化

- 应用语言类型为 `zh-CN | en-US`，定义在 [`src/shared/i18n/index.ts`](../src/shared/i18n/index.ts)。
- 第一次创建 Vault 时，Electron 的 `app.getLocale()` 以 `zh` 开头则选择 `zh-CN`；其他 locale（包括缺失值）选择 `en-US`。`zh-TW` 等中文 locale 当前也映射到简体中文资源包。
- 语言保存在 `AppSettings.language`。后续启动以持久化值为准，不随操作系统语言变化。
- 旧 Vault 缺少 `language` 时，[`normalizeAppSettings`](../src/electron/storage/settings-schema.ts) 使用本次启动的系统语言作为 fallback。加密存储会检测规范化后的状态变化并重新落盘，因此迁移只发生一次。

主进程在创建 repository 前先设置系统推导语言，以便初始化和错误文案使用正确资源；Vault 解锁后再切换到保存的语言。renderer 的 [`main.tsx`](../src/renderer/src/main.tsx) 会先通过 preload 读取设置并调用 `setLanguage`，然后动态导入 React 应用，避免初始界面闪现错误语言。

用户在「设置 → 通用 → 外观与行为」中保存新语言后，renderer 与主进程立即更新活动资源包，并在 150ms 后轻量重载页面。重载可确保模块级常量、标题提示词、提示建议与内置 Skill 元数据全部重新物化为目标语言。

## 资源包与运行时 API

| 文件                                                                      | 职责                                                                               |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| [`src/shared/i18n/locales/zh-CN.ts`](../src/shared/i18n/locales/zh-CN.ts) | 简体中文翻译；key 为英文源文案                                                     |
| [`src/shared/i18n/locales/en-US.ts`](../src/shared/i18n/locales/en-US.ts) | 仅语义「逃生舱」key：同一英文需区分不同中文时使用                                  |
| [`src/shared/i18n/index.ts`](../src/shared/i18n/index.ts)                 | locale 解析、活动语言状态、`MessageKey` 类型、资源查找与参数插值                   |
| [`scripts/localize-renderer.mjs`](../scripts/localize-renderer.mjs)       | key 抽取、增量翻译初稿 `en → zh-CN`、人工覆盖与 `check` 校验                       |
| [`scripts/migrate-i18n-keys.mjs`](../scripts/migrate-i18n-keys.mjs)       | 一次性 codemod，将旧「中文为 key」方案翻转为「英文为 key」（保留备查，带幂等守卫） |

**英文源文案即 message key。** 用户可见文案以英文书写并传入 `t()`：

```ts
import { t } from '../../shared/i18n'

t('Fetched {value0} models.', { value0: models.length })
```

在 `en-US` 下，普通 key 直接返回自身（仅做占位符插值）；在 `zh-CN` 下使用 `zh-CN.ts` 中经审校的中文译文。`t(key, values)` 先读活动语言包，回退到 `en-US` 逃生舱包，最后回退 key 本身——因此未翻译的 key 会优雅降级为可读英文，而非裸标识符。占位符支持命名（`{count}`）与 `{value0}` 位置形式；key 与其中文 value 的占位符名称必须逐项相同。`key` 参数类型为 `MessageKey`（`keyof typeof zhCN`），拼写错误、迁移遗漏或引用已删除 key 都会在编译期暴露。日期和数字应使用 `getLanguage()` 配合 `Intl.DateTimeFormat` / `toLocaleString`，不要固定写死 `zh-CN`。

### 语义逃生舱 key

大多数文案直接以英文为 key。例外是 `en-US.ts` 中少量**语义逃生舱 key**，用于同一英文需渲染为*不同*中文的场景。典型例子是中文 Agent 续传词表——`继续`、`接着来`、`接着做` 对应英文 `Continue`，`重试`/`再试一次`/`再次尝试`/`重新尝试` 对应 `Try again`，但每条都必须保持为不同的中文续传短语，否则 `agent-continuation` 检测会失效。每组中一条取英文明文 key（`Continue`、`Try again`），其余成为语义 key（`agentContinuation.continueVariant1`、`agentContinuation.tryAgainVariant1` …），其 `en-US` 值等于共享英文，`zh-CN` 值保留各自的中文。仅当出现新的「同英文/异中文」碰撞时才新增逃生舱 key。

## 抽取与生成脚本

脚本扫描 renderer、Electron、shared TypeScript 源文件和内置 Skill 定义：

```powershell
# 抽取 key（t() 调用点字面量 + 内置 Skill 资源字段）并重建简体中文包。
# 仅为新增 key 请求机器翻译。
node scripts/localize-renderer.mjs generate

# 校验：t() 外的中文或 key 不在资源包中则失败。
node scripts/localize-renderer.mjs check
```

`generate` 收集每个 `t()` 字符串字面量第一参数（含条件表达式的两个分支）以及内置 Skill 的 `name`/`description`/`systemPrompt`/Markdown-`content` 字面量。它保留既有中文译文，只为新增 key 请求机器翻译初稿。解析优先级为：`reviewedZh` 人工覆盖 → 既有翻译 → 经 `normalizeZhByContext` 规范化的机器翻译初稿 → 回退到英文 key 本身。语义逃生舱 key 必须已有中文值或显式加入人工覆盖，不会从不透明标识符直接机器翻译。新增 key 时该命令可能访问外部翻译服务；运行后必须审查 diff，不能把生成结果视为已经完成语言评审。

`check` 在以下情况失败：(1) `t()` 参数之外存在中文（含应包装的裸中文回退值）；(2) `t()` 字面量 key 不在 `zh-CN.ts` 中。每次文案变更后都应运行。

Python、Shell 等可执行 Skill 文件不是用户文案，不得进入资源包或机器翻译。只本地化 Skill 的名称、描述、系统指令，以及 `kind === 'markdown'` 的文件；内置 Skill 的代码资产必须保持字节语义稳定。

## 术语

英文产品与协议术语应使用规范词（即 message key）：

- OpenAI：`Responses API`、`Chat Completions API`、`reasoning`、`reasoning effort`。
- Anthropic：`Anthropic Messages API`、`adaptive thinking`、`manual extended thinking`。
- MCP：`MCP server`、`MCP client`、`MCP tool`、`Streamable HTTP`、`legacy HTTP+SSE`。
- OpenRouter：`provider`、`provider fallback`、`Zero Data Retention (ZDR)`、`native web search`、`latency`、`throughput`。
- 安全与备份：`plaintext`、`OS secure storage`、`WinZip AES-256 (AE-2)`。
- 聊天数据：实体使用 `conversation`；Agent 恢复使用 `checkpoint`；Skill ZIP 使用 `skill archive`。

新增或明确修订的文案应遵循下表。key 翻转迁移刻意逐字节保留了既有中文值，因此 `zh-CN.ts` 中的历史条目在另行完成文案审校前仍可能保留旧术语。当同一英文在不同语境需要不同中文时，新增语义逃生舱 key，而不是强行共享翻译。

| 英文 key 术语               | 规范中文 | 说明                                                              |
| --------------------------- | -------- | ----------------------------------------------------------------- |
| `provider`                  | 服务商   | 新增及已审校产品文案的首选；迁移保留的历史译文仍可能使用 `供应商` |
| `conversation`              | 会话     | `session` 仅用于底层协议连接                                      |
| `web search`                | 网页搜索 | 不得使用 `网络搜索`/`互联网搜索`                                  |
| `reasoning effort`          | 思考强度 |                                                                   |
| `plaintext`                 | 明文     | 不得使用 `纯文本`                                                 |
| `archive` / `skill archive` | 压缩包   |                                                                   |
| `checkpoint`                | 现场     | 用于 Agent 中断恢复                                               |
| `MCP server`                | MCP 服务 |                                                                   |

## 校验与提交清单

更新用户可见文案后运行：

```powershell
node scripts/localize-renderer.mjs generate
node scripts/localize-renderer.mjs check
pnpm typecheck
pnpm test
```

[`tests/i18n.test.ts`](../tests/i18n.test.ts) 当前验证：

- 中文包 key 不含汉字，且 key 与中文 value 的占位符集合一致；
- `en-US` 逃生舱 key 是中文包子集，且不含汉字；
- 英文 key 不使用禁用的机器翻译措辞（`supplier`、`vendor`、`MCP service`、`prompt word`、`thinking intensity` …）；
- 系统 locale 的首次语言决策；
- `setLanguage` 切换、动态参数插值、英文下普通 key 返回自身、逃生舱 key 解析；
- 可执行内置 Skill 资产不进入资源包；
- 五个内置 Skill 能物化为经过人工审校的英文名称与 Markdown 指令。

代码审查还应人工检查语境、按钮长度、英文单复数、错误提示可操作性，以及新增模块级常量是否需要切换语言后重载；自动化测试不能替代这些检查。
